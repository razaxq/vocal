# 如何判断纠错是否有收益

先区分两件事：文字是否更接近实际口述，以及文字能否正确输入目标应用。
“焦点变化”、粘贴失败、等待时间属于使用体验，不能混入识别准确率。

## 建议的配对测试

1. 收集 50–100 条真实口述，覆盖短句、长句、口语、专业词、人名、数字、中英混合，也要包含本来就识别正确的句子。不要只挑新模型能改好的例子。
2. 人工根据录音写参考文字，保持原意和口语，不把润色稿当正确答案。无法确定的句子先不评分。
3. 固定语音模型、分段、清理、词库和热词，把同一份识别文本分别交给“不纠错、MacBERT、句子模型”。不要分别重说三遍。
4. 先看每句差异，再看总数。必要时隐藏模型名称，请使用者判断哪份更接近录音。
5. 另外用实际输入应用测试从松键到输出的耗时和输入失败次数。纠错工具本身不会模拟这些行为。

观察指标：

- **字符错误率**：改成参考文字需要的最少增、删、改字符数，除以参考文字字符数，越低越好。此工具忽略空白和标点，但保留数字和英文字母大小写；标点应单独检查。
- **改善/退步句数**：相对不纠错，错误字符变少/变多的句子数量。错误数一样也可能换了另一种错法，仍需检查逐句结果。
- **正确句误改**：原本正确的句子被改动了多少，其中多少产生新的文字错误。少量样本中没有误改，不代表误改率为零。
- **耗时中位数与 P95**：模型计算时间，不含冷启动、语音识别、标点、粘贴与界面延迟。P95 使用最近秩方法；小样本下几乎等于最慢的一条。
- **人名、数字、热词和含义**：单独人工核对。总体错误率较低也不能抵消关键数字被改错。

## 本地对比工具

`native/scripts/evaluate-correction.py` 接受 UTF-8 JSONL，每行一条：

```json
{"id":"001","text":"完全就是给拦柜用的","reference":"完全就是给懒鬼用的","hotwords":[]}
```

`text` 应是同一份已完成口语清理的文字；`reference` 必须人工核对，未知时省略。
省略参考文字的样本仍运行并计时，但不会计入准确率。报告含输入、输出和纠错决策，保存在本地。

```powershell
python native/scripts/evaluate-correction.py `
  --app <本地调试程序的完整路径> `
  --models data/models `
  --cases native/tests/fixtures/correction-evaluation.jsonl `
  --output data/correction-evaluation/result.json
```

开启基础词库时加 `--dictionary-enabled`。需要匹配自己更新过的词库时，再指定 `--dictionary <catalog.json路径>`。
运行依赖已下载的 MacBERT 和 CEC3 模型；开发构建还需 Qt/编译器 DLL 路径，完整打包目录内的程序不需要另设路径。

本工具比较**纠错阶段**：MacBERT 做一次片段纠错及一次保留片段结果的全文复核；CEC3 做一次全文纠错。
二者使用同一输入和热词。它不模拟多片段调度，不重新执行清理或标点；内置样本也不包含可被清理阶段消除的重复词。
两次 MacBERT 进程的加载时间另行记录，不当作实际应用的加载时间。文件哈希用于确认本次程序和样本版本。

内置样本主要是人工构造的回归题，并非随机抽取的真实录音测试集。
不能用它宣布新模型整体更强，或把纠错阶段的分数当作最终语音识别准确率。
