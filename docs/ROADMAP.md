# 路线图

原则：**先杀红色风险，再加功能。** 每一项的完成标准是「在真机上跑通」，不是「代码写完了」。

M0~M3 已经走完，下面第一节是已经立住的地基，第二节起才是还没做的事。

## 一、已经验证过的（Windows 实机）

这一节是**证据**，不是计划。写在这里是为了让后来的人知道哪些假设已经不用再怀疑。

### 三个红色风险全部通过

| 风险 | 结论 | 怎么验的 |
|---|---|---|
| **R2** 原生模块能否在 Electron 里加载 | ✅ 通过 | `npm run m0:native` —— Electron 44.3.0 / Node 24.20.0 / x64 上 sherpa-onnx-node v1.13.8（onnxruntime 1.28.2）正常加载，三个 Recognizer 导出齐全。**这是最大的一个风险，ASR 方案不用换了。** |
| **R1** SendInput 能不能可靠地把字打进别人的窗口 | ✅ 通过 | `npm run m0:roundtrip` 42/42 逐字符一致（中英数破折号），`npm run m0:inject` 48/48 被系统接受。koffi 结构体对齐正确：`sizeof(INPUT) = 40` |
| **R3** `focusable:false` 的面板会不会夺焦 | ✅ 通过 | `npm run m0:focus` —— `showInactive()` 之后前台窗口句柄未变 |

### 实测性能（已写回 [DESIGN §5](DESIGN.md)）

- SenseVoice 解码 5 秒片段 **107ms**（原估 80~250ms）
- 补标点 **3ms**（原估 20~50ms）
- 三个模型加载合计 ~2s（两进程并行约 1s），磁盘 **531 MB**

107ms 已经完全能藏在下一段录音里，**DirectML 因此被降级为「不值得做」**——省下的几十毫秒用户感知不到。

### 路上踩到并已修掉的坑

- **`RightControl` 这个键名根本不存在**，uiohook 的枚举叫 `CtrlRight`。键名白名单收进 `src/shared/hotkeys.ts`，配置校验 / 设置下拉 / 热键注册三处共用
- **Electron 44 的 `clipboard.readText()/writeText()` 改成返回 Promise 了**，老写法会把 `[object Promise]` 写进剪贴板
- **SenseVoice 对 5 秒纯静音会幻觉出「我.」**（R7）。已加语音门限 + 定稿健全性两道防线（`src/shared/audioGate.ts`）
- **`final-only` 档位一个字都出不来**：stream.ts 里注释承诺的「主进程静音切段」从没实现过。补上 `SilenceSegmenter`
- **`@vitejs/plugin-react@6` 要 `vite@8`**，而 `electron-vite@5` 的 peer 只到 `vite@7`，固定用 `^5.2.0`
- **增量 `npm install` 会把非本平台的 optional 依赖从 lock 里剔掉**，Windows 上就装不到 `sherpa-onnx-win-x64`。改依赖后必须删掉 `node_modules` 和 lock 重新解析

`npm test` 35 个单元测试：口语清洗、历史存储、语音门限、静音切段。

### 已经做完的功能

热键三种模式（按住 / 开关 / 双击）+ 防抖 · 流式 + 分段定稿并行流水线 · 规则层口语清洗 ·
LLM 书面化整理（`onFinish` / `rolling`）· unicode + 剪贴板双通路注入与失败降级 ·
Esc 取消并撤回 · 悬浮面板 · 完整设置窗口（按流水线分页）· 模型下载与切换（免重启）·
便携 / 安装双模式 · 自动更新 · 历史与统计 · 托盘 · 单实例

## 已经否掉的

- **DirectML GPU 加速。** 定稿只要 107ms，省下几十毫秒用户感知不到，
  而代价是换带 DML 的 onnxruntime 并自己补 DLL。见 [ADR-0004](adr/0004-prior-art.md)
- **better-sqlite3 存历史。** 它是整个依赖树里唯一需要 node-gyp 的，
  为了保住「零编译依赖」换成了 JSONL。见 [ADR-0006](adr/0006-no-native-build.md)
- **把 ququ 作为 submodule。** 技术栈交集太小，见 [ADR-0001](adr/0001-no-ququ-submodule.md)
- **清洗的「激进」档**（连「说实话」「其实呢」也删）。这些词承载语气，删掉之后句子意思变了，
  而这一层只该去掉「说话时的噪音」，不该替用户重写句子
- **独立的「引擎档位」设置。** 它其实就是模型选择的结果，两个说法讲同一件事
