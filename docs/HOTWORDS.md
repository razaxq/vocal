# 雾凇基础词库与个人热词

## 来源

基础词库来自 [iDvel/rime-ice](https://github.com/iDvel/rime-ice) 的 `cn_dicts/base.dict.yaml`，遵循上游 GPL-3.0 许可。原始词典保留在源码仓库的 `resources/dictionaries/rime-ice/`，只供生成和校验使用。安装版和便携版仅携带运行时读取的 `catalog.json`、许可证全文、来源说明和上游声明，不携带原始词典。

`catalog.json` 记录原始提交 SHA、文件 SHA-256、词库日期、数量及生成规则。完整读取基础词库，按词去重并保留多音读法；当前快照为 541,809 个词条，不包含雾凇的扩展、腾讯或英文词库。界面只预览前 100 词，完整数据交给定稿进程，避免大量词表反复传到界面。这不是最新热搜词表。

此前手工整理的 208 词已删除；缺少雾凇来源信息的旧缓存不再加载。个人热词及原有开关设置保留。内部配置键 `networkHotwords` 为兼容已有设置而保留。

## 更新

- 仓库的 `dictionary` 工作流每周同步一次雾凇上游，也支持手动触发。只有同步、生成及测试通过后才提交词典数据。
- `npm run sync:rime` 将全部下载固定到同一个上游提交，保存原词典和许可，再自动生成完整检索词库。不要手动编辑派生词表。
- 客户端每周检查本仓库发布的派生词表，支持手动更新。下载失败继续使用本地词库；运行期间每天重试，重启也可重试。
- 更新不需要重新下载模型；只有词表数据会联网下载，不上传录音或个人热词。

## 识别行为

- 全量词库建立读音索引，每句从初稿的汉字读音中召回同音候选（忽略声调）；长词优先，同长度按上游词频排序。每个读音最多 8 个候选，每句最多 64 个。全部词条参与索引，候选限制只控制本次送入引擎的规模。
- 查询最多读取初稿前 512 个字符，不跨标点或英文拼接。多音字由 pinyin-pro 结合文本确定读音，词库中的多种读法保留；没有实现近音模糊匹配。初稿读音错得过多时可能无法召回正确词。
- 流式加定稿模式使用流式初稿检索，再用原音频定稿；仅定稿模式先识别一次，找到候选才用原音频识别第二次，因此可能增加延迟。候选不直接替换文字，最终由语音模型解码。
- 个人词权重 2.5，召回的基础词权重 1.5，同名词保留个人权重。这些数值不是准确率最优的实验结论。
- 两类热词仅交给支持热词的 Zipformer 定稿模型。流式实时预览不使用；仅流式模式、SenseVoice 和 Paraformer 定稿均不使用热词。
- 开启「清理时保留热词」时，个人热词纳入口语清理保护。
- 个人热词采用本地编辑草稿，点击保存才写配置，中文输入法组词期间不会保存；重复点击合并为一次。热词变化不重载模型，基础词库版本变化才重建词库索引。
- 更新只在当前语音输入结束后应用。关闭基础词库不删除个人词。

## 悬浮窗与验证

定稿结果替换对应段的流式预览，保留随后段落；定稿异常时仍回落到流式文本。完成所有段的写入后才生成历史，最终文字保留到悬浮窗退场。

`npm test` 覆盖全量生成、候选召回、缓存更新、连续段落和历史；`npm run build && npm run m0:hotwords` 验证构建后的中文组合输入、保存去重及失败重试。`npm run m1:hotwords` 使用本地默认 Zipformer、标点模型和 Paraformer 附带样例音频验证实际解码与模型构造次数（需先构建并下载这些模型），不代表准确率评测。

## 纠错学习的边界

当前版本没有观察外部应用的编辑内容，也没有自动学习修改记录。

后续可先提供用户明确确认的「记住这个词」，将修正后的词保存为个人热词。若实现自动检测，需要关联本次语音输入所在的输入框、输入前后文本及编辑范围，并区分识别纠错与用户改写。Windows UI Automation 的支持取决于目标应用，不能保证覆盖所有软件。
