## 修复的运行问题

### 最终长文本批量替换（2026-09-18）

- TextOutput 从逐字符退格改为选中旧后缀后替换；未变化的前缀保留。自动输入策略允许长文本替换走剪贴板，不再强制改成 Unicode 逐字发送。明确选择 Unicode 的用户仍保留该偏好。纯删除只发送一次退格以删除选区。
- Windows 标准 Edit 控件校验光标前旧文字后使用 EM_SETSEL；其他支持 UI Automation TextPattern 的控件校验选区文本后调用 Select。不支持文字范围接口的控件兼容使用一批 Shift+Left 选择事件，不发送 Ctrl+A。该兼容路径仍受目标应用处理选择事件的速度影响。
- 精确范围路径遇到旧文字不匹配、已有用户选区或焦点变化时拒绝替换；失败后禁用本次会话的进一步自动替换。兼容键盘路径保留原有光标位置假设，无法核对目标编辑器实际文字。
- 公共前缀按字素边界处理，避免拆开代理对、组合音标和 emoji。连续自动粘贴共用原始剪贴板备份，用户中途复制新内容时保留新内容。
- 4 组 QtTest 通过，包括新增长文本一次选区/一次粘贴、删除选区、Unicode 边界、选择失败不重试及剪贴板恢复测试。
- 新增 `vocal-native-probe --replace native|qt [--replacement-moved]` 独立窗口探针，覆盖原内容前后都保留的多行 Unicode 替换。当前实机运行被 Windows 前台限制阻止（SetForegroundWindow 返回 false），程序正确拒绝输入；不能计作真实编辑器替换成功或速度提升实测。证据：`data/replacement-check-20260918/`。实际应用兼容性仍需用户试用。
- 参考 Windows 接口：[EM_SETSEL](https://learn.microsoft.com/en-us/windows/win32/controls/em-setsel)、[UI Automation TextRange](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nn-uiautomationclient-iuiautomationtextrange)。

### 短停顿分段后的识别上下文与标点（2026-09-18，早期验证）

其中“仅最后一次标点”的行为已由下方累计原文预览方案替代，整段音频复核也已在后续修复中移除；此节保留当时的回归证据。

- 用户反馈的 12.2 秒、4 段会话中，历史 raw 与最终 text 相同；错字与错误句号已存在于原始识别文本。用当前 MacBERT 重放用户提供文本未修正错字，也未把对应正确句子改坏；没有原始录音，不能判定该次音频的确切错误原因或声学质量。
- 分段识别与完整音频复核均显式关闭外置标点处理。最终全文纠错之后仅统一调用一次标点模型；仅流式模式也走同一路径，SenseVoice 2024 保留自身标点，不叠加 CT-Transformer。
- 多段、总长不超过 120 秒的会话，在结束时使用完整 PCM 再做一次离线识别，恢复跨片段上下文；单段不重复识别。缓存是有界临时文件，结束/取消后删除。超长会话或复核失败保留逐段结果，不强制拼接无限长音频。
- 分段文本合并保留英文词间空格，中文和连续数字不插入额外空格。
- 工作进程协议测试验证两段“因为现在已经”/“五点十九分十五秒了”均不调用标点，合并后调用一次，结果不含“已经。”。六种分段/模型组合验证实际标点调用一次，启用离线模型时完整音频复核一次。
- 公开语音中插入句内 800 ms 停顿，确认实时分成多段后，最终结果与同一份完整音频直接识别的结果一致；仅执行一次标点处理。完整流程、连续会话、静音、仅流式和悬浮窗过渡回归通过。
- 本轮 4 组 QtTest、5 项工作进程集成测试和 QML lint 通过。分段数据见 `data/quality-check-20260918/segmentation/results.json`。完整复核需要额外一次识别；上述回归不等于总体识别准确率已提升，也不保证能修复所有同音字。

### 触发后录音启动延迟（2026-09-18，本地代码与流程验证）

- 默认开启“麦克风预热”，未触发时只排空设备数据，不保存、不识别；关闭总开关/退出释放设备。关闭预热在当前录音结束后释放，不中断已经触发的录音。
- 采集移到独立线程，使用程序自有的有界 PCM 邮箱；界面繁忙时继续采集。设备开启不再阻塞界面绘制，停止先排空尾包，取消使旧会话回调失效。
- 新增 `native-capture` 模拟设备测试，验证预热丢弃空闲数据、复用设备、预热期间触发保留首包、慢启动期间关闭、设备切换、界面阻塞时无丢帧及取消隔离。模拟设备结果不等于真实硬件延迟验收。
- 会话/音频缓存初始化提前到麦克风打开之前；连接 readyRead 后主动读取已可用的数据，避免首包早于初始化或通知连接。
- 麦克风打开后再异步恢复未就绪的模型，保留已就绪模型；停止或取消后，过期的模型恢复回调不会执行。
- Windows 使用设备原生采样格式，请求 40 ms 采集缓冲；实际大小由设备后端决定，未将请求值当作实测延迟。
- 悬浮窗收到首批非空音频前显示“麦克风准备中”，之后显示“正在听”；静音采样也算采集就绪，不要求用户先说话。
- `capture_startup.py` 通过：20 ms 公共 PCM 包在模型加载期间进入缓存，冷/热两次完整文本一致。3 组 QtTest 和 QML lint 通过。
- 初次同步探针曾打开失败/超时。改为独立线程与预热后，本机默认设备的新探针通过：预热 2 秒后首包耗时计为 0 ms（毫秒分辨率），48 kHz 连续约 3 秒共 144480 个单声道采样，界面线程约 5 秒内运行 499 次心跳；未保存音频。证据：`data/capture-startup-check-20260918/warm-microphone.jsonl`。这不保证其他设备、休眠恢复或首次启动也有相同延迟，实际讲话漏字仍需用户试用。
- 本轮 4 组 QtTest（新增 7 个采集用例）和 QML lint 通过。
- 预热对比：本机默认 Sonar 虚拟麦克风 48 kHz，交替各测 10 次；发起采集到首包的中位数，开启 1.58 ms、关闭 100.44 ms，最慢分别 13.73 ms 与 1104.78 ms。未剔除慢启动；不含键盘/鼠标触发等待及 Sonar 的上游声学延迟。原始数据、环境与限制见 `data/capture-latency-20260918/`；可用 `native/tests/capture_latency.py` 复现。

### 连续分段与全文纠错（2026-09-18，本地验证）

后续实测反馈修订：

- 默认增加自动分段，手动停顿设置仅在关闭自动分段时显示并生效。短停顿阈值依据已观测的句内停顿节奏和片段长度调整，不再统一等待 1500 ms。
- 16/44.1/48 kHz 下，320 ms 停顿可分段且保留后一字轻起音；同样的 320 ms 在较慢的句内停顿节奏下继续等待。200 ms 短暂音量低谷不会切段。
- 真实公开音频暴露出启动时 40 ms 瞬间噪声被提前识别为多余英文的问题；现自动分段先积累至少 100 ms 的有效音量帧，再使用短停顿规则，保留启动音频与后续语音上下文。新增回归覆盖该边界。
- 四种手动组合及两种自动组合通过。自动组合使用 400 ms 间隔，未开启流式模型也能在录音期间提交结果，三段按顺序合并，无多余启动噪声转录。证据：`data/automatic-segmentation-check-20260918/results.json`。
- 3 组 QtTest、QML lint 和自动/手动界面截图检查通过。此处验证短停顿响应与音频完整性，不宣称按语义精确找到每个逗号。

- 以 20 ms 帧检测停顿，在确认的静音区内部划分 PCM；16/44.1/48 kHz、不同输入包大小及跨包边界测试确认拼接后逐采样一致，没有丢失或重复音频。
- 短于阈值的停顿不切段，连续 31 s 语音不再触发原来的 30 s 强制切段。180 s 静音缓存有界；单段 120 s 上限、结束及重置测试通过。
- `segmentation_pipeline.py` 用三段公开中文音频与 1500 ms 停顿测试仅定稿、定稿加流式、仅流式、关闭纠错四种配置；均在录音期间提交内容，最后得到三段文字和一条历史。
- 未启用流式模型时可显示定稿中间结果；启用纠错时，会话结束后只执行一次全文纠错。长文本样例验证最后一个窗口参与纠错，英文受保护内容保持。
- 悬浮窗文字开关默认开启，关闭后显示紧凑波形和状态；两种截图及隐藏流程通过。原有两种布局各连续两次录音的首帧与定稿过渡检查通过。
- 界面测试在进场完成后模拟松开热键，避免冷启动首帧晚于固定 500 ms 时误判为退场闪烁；它不代表首帧延迟的性能验收。
- 构建、QML lint、3 组 QtTest 通过。证据：`data/segmentation-check-20260918/results.json` 及同目录截图。

分段依据音量和停顿，并非语义分类。上述固定样例验证音频边界与流程，不代表总体识别或纠错准确率；真实麦克风的轻声、噪声和临界停顿仍需用户试用。

### 累计标点预览、输出时机与粘贴串行化（2026-09-18）

- 原文与显示结果分离。每次新增定稿/纠错片段，对累计未加标点文本生成预览；标点请求合并、旧结果丢弃、相同来源复用。整段识别复核与全文纠错仍保留，因此前文确实变化时仍会修正，不能保证永远只变最后一句。
- 输出时机为 final / preview。final 模式录音期间零写入，结束后一次输出；preview 模式在录音期间同步更新，最后相同内容不再写入。旧 segment / live 配置迁移到 preview；新配置默认 final。
- 剪贴板粘贴和 Unicode 输入串行化，等待上一笔完成后处理最新待写入内容。支持标准 Edit/UI Automation 文字范围的应用核对光标前实际文本；不支持读取范围的编辑器使用 300 ms 兼容等待。核对超时或焦点变化停止后续输入，不盲目重试。剪贴板恢复在输入完成之后，用户的新复制内容优先保留。
- QtTest 覆盖延迟 240 ms 才读取剪贴板、连续预览合并、最终相同文本不重复粘贴、取消/连续会话隔离、焦点变化和原剪贴板恢复。这些模拟测试不等于所有第三方编辑器均已实机验收。
- 悬浮窗三种模式：全部内容先增宽再增高、最新三行、不显示文字。超过屏幕可用高度时，全部内容模式允许滚动，窗口不接受焦点；另外两种模式继续穿透鼠标。
- 六组真实 ASR/CSC 分段组合检查完整原文标点来源不含上轮标点、录音期间的预览、两种输出时机、最终整段复核及一条历史。公开音频句内插入 800 ms 停顿后，最终文字仍与同一完整音频直接识别一致。
- 构建、四组 QtTest、QML lint 和浅/深色 12 张悬浮窗布局截图已检查。三种模式各连续录音两次，首帧和录音到定稿过渡没有隐藏/透明度闪变；静默与连续会话回归通过。证据目录：`data/preview-check-20260918/`。实际第三方应用粘贴仍需本机试用，尤其是缺少 UI Automation 的自绘编辑器。
