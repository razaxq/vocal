# Vocal

**按住一个键说话，松开，文字出现在你正在用的那个输入框里。**

不是「能把语音转成字」，而是让语音真的能当成一种输入法用 ——
任何应用、任何输入框、全本地、不抢焦点。

[下载](https://github.com/razaxq/vocal/releases) · [怎么用](#怎么用) · [做不到什么](#做不到什么)

## 下载

去 [Releases](https://github.com/razaxq/vocal/releases) 拿最新版，两个包挑一个：

| 包 | 适合 | 你的数据在哪 | 自动更新 |
|---|---|---|---|
| **`Vocal-Setup-x.y.z.exe`** | 大多数人 | `%APPDATA%\Vocal` | ✅ 后台下载，退出时装上 |
| `Vocal-x.y.z-win.zip` | 想随身带、不想装东西 | 解压目录里的 `data/` | ❌ 只在设置里提示有新版 |

> **第一次运行会弹 SmartScreen 蓝框**，点「更多信息 → 仍要运行」。
> 因为没买代码签名证书（一年几百刀），不是因为程序有问题。介意的话可以自己 clone 下来构建。

装好之后还差一步：**打开设置 → 识别 → 点一个模型开始下载**（约 500MB，只下这一次）。
模型没打进安装包，否则安装包会变成 500MB+，而且每次更新都要重下一遍。

## 怎么用

**按住右 Ctrl 说话，松开。** 就这样。

说话的时候光标附近会出现一条悬浮窗，实时显示识别到了什么。每说完一句，那句话就
直接出现在你原来的输入框里 —— 不用复制粘贴，不用切窗口，焦点始终在你的应用上。

- **说错了？** 录音过程中按 <kbd>Esc</kbd>，已经打出去的字会被撤回。
- **不想一直按着？** 设置 → 触发 → 改成「按一下开始，再按一下结束」。
- **停顿一下就被断句了？** 设置 → 识别 → 把「停顿多久算一句」调大（默认 1.5 秒）。
- **人名、术语老是识别错？** 设置 → 识别 → 热词，一行一个填进去。
- **想要书面语而不是大白话？** 设置 → 整理 → 填一个 OpenAI 兼容的接口。
  这是唯一需要联网的功能，默认关着。

设置窗口按「一次语音输入依次经过什么」排：触发 → 识别 → 清洗 → 整理 → 上屏。
不知道某个选项在管什么，看它在哪一页就大概知道了。

## 它能做到什么

- **全本地。** 语音、文字、历史都只存在你这台电脑上，不传任何服务器。断网照常工作。
- **说的时候就在出字。** 不是说完等一大段。长篇口述是每隔几秒出一批，不会憋到最后。
- **中英混排。** 「这个 bug 在 useEffect 里」能正确出，不会变成「这个八哥在优思艾费克特里」。
- **自动标点。** 顺便把「二零二六年三点五万」写成「2026 年 3.5 万」。
- **自动删口水词。** 「嗯」「呃」「那个」「就是说」和「我我我」这类口吃重复会被删掉。
  叠词（刚刚 / 看看 / 谢谢）和实词位置的「这个方案」不会被误伤。
- **热词表。** 锁住人名、项目名、缩写，同时保证它们不被上面那条规则删掉。
- **书面化整理**（可选，需联网）。长输入说完后把口语句式改写成书面表达、合并被停顿
  切碎的句子、自动分段。不配接口就没有这一层，其余功能一个不少。

## 做不到什么

这几条是结构性的，不是还没做：

- **管理员权限的窗口注入不进去。** Windows 的 UIPI 拦跨权限级别的输入模拟。
  给 Vocal 提权会导致反向的问题（普通程序反而注入不了），两头不可兼得。
- **安静环境是前提。** 这是语音输入相对打字的本质劣势，没有解法。
- **事后改字比打字麻烦。** 打字能边想边改，语音只能说完再改。
  所以它最适合写邮件、写文档、写 commit message、聊天，不适合写代码和填表单。
- **模型常驻要吃几百 MB 内存。** 三处可以压：只用流式模型、只用定稿模型、
  或者靠默认开着的「空闲 10 分钟卸载模型」。实时占用在设置的「关于」页按进程列着。
- **只有 Windows 10 1809+ / x64。** 代码里没有为跨平台留抽象层。

## 隐私

识别全在本机跑（sherpa-onnx + ONNX Runtime），不需要联网、不需要账号、不收集任何东西。

唯一会出网的是「整理」那一层 —— 它要把文字发给**你自己填的**大模型接口。
默认关着，关着就是完全离线。

## 给开发者

```powershell
npm install        # 纯预编译依赖，不需要 Visual Studio / Python，不跑 node-gyp
npm run models     # 下模型（也可以跳过，启动后在界面里下）
npm run dev
npm test           # 35 个单元测试，不需要模型
npm run dist       # 打包，产物在 release/
```

**环境**：Windows 10 1809+ / x64、Node 22+。解压模型用系统自带的 `tar`（Win10 1803+ 自带）。

| 层 | 选型 | 为什么 |
|---|---|---|
| 壳 | Electron 44 + electron-vite | 要渲染进程的 `AudioWorklet` 做低延迟采集 |
| 识别 | sherpa-onnx（流式 Paraformer + SenseVoice + CT-Transformer） | C++/ONNX，有预编译 Node 绑定，无 Python 依赖 |
| 进程模型 | 主进程 + 流式进程 + 定稿进程 | 两个 ASR 进程并行，说下一句时上一句已在另一个核上定稿 |
| 注入 | koffi FFI → `SendInput` + `KEYEVENTF_UNICODE` | 无需编译工具链，等价于真的打字 |
| 热键 | `uiohook-napi` + Electron `globalShortcut` | 前者提供 keyup（按住说话），后者能吞掉组合键 |
| 存储 | JSONL + electron-store | 零编译依赖是硬约束，见 [ADR-0006](docs/adr/0006-no-native-build.md) |

- [`docs/ROADMAP.md`](docs/ROADMAP.md) —— 验证过什么、还差什么、否掉了什么
